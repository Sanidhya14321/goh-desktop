# Make GoHarness easier to work in

The highest-impact improvement is to keep the user’s intent intact as they move between setup, sessions, approvals, and terminals. VS Code and Zed surface the folder that owns an action. VS Code’s experimental Inbox gives pending agent input a consistent place to find. Warp and Windows Terminal make shells easier to identify and search after several are open. The first implementation pass will apply those patterns to the existing GoHarness workspace by completing the first-session flow, centralizing navigation to pending input, and improving project and terminal switching. This plan draws on official product documentation and a source audit of GoHarness. ## Carry the first session through setup

VS Code’s agent quickstart makes the project and permissions part of the first task. The Codex app quickstart presents setup, folder selection, and the first prompt as one journey. Cursor makes exploration easy to find through its Ask mode. In the audited GoHarness flow, New Session returns after opening the folder picker or provider dialog, so a user who completes setup has to issue the original action again. **Keep the chosen project and resume New Session once it is ready.** Treat cancellation as an exit from the pending action, and keep existing provider settings on the direct path. Offer a starter action that fills in a read-only request, such as mapping the project structure. The user reviews the text and sends it through the existing composer. An outcome label such as “Explain this project” describes the starter accurately. [VS Code agent quickstart](https://code.visualstudio.com/docs/agents/quickstart) · [Codex app quickstart](https://learn.chatgpt.com/docs/app) · [Cursor Agent modes](https://cursor.com/help/ai-features/agent)

## Lead users back to the request that needs them

VS Code’s experimental Inbox aggregates questions, approvals, and errors across projects and leads users into the corresponding session. GoHarness already has live challenge frames and session-specific input routing. An app-wide **Needs input** list can use those frames to identify the project, session, and type of request and focus the exact challenge. A request stays visible until it is resolved or the run ends. A proposed edit continues to show the engine’s pre-execution preview and its project context. Keep allow-once and deny explicit in the owning session, and preserve the draft in the session the user left. [VS Code session organization](https://code.visualstudio.com/docs/agents/run/sessions/organize-sessions) · [VS Code approvals](https://code.visualstudio.com/docs/agents/run/approvals)

## Make every switch preserve its project and pane

VS Code disambiguates identical file names with a folder label and can open a terminal from a specific Explorer folder. Zed keeps project-local tabs and threads and offers a Cmd/Ctrl+Shift+P command palette. For GoHarness, show visible parent context when project names collide, preserve the full path for identification, and add the shortcut alias while retaining the existing shortcut. A project-specific terminal action should start the shell in the chosen folder and leave the active agent session where it was. A terminal label can show the project where the shell started. Live working-directory tracking would depend on additional shell integration. [VS Code multi-root workspaces](https://code.visualstudio.com/docs/editing/workspaces/multi-root-workspaces#general-ui) · [VS Code terminal basics](https://code.visualstudio.com/docs/terminal/basics) · [Zed command palette](https://zed.dev/docs/command-palette) · [VS Code shell integration](https://code.visualstudio.com/docs/terminal/shell-integration#current-working-directory-detection)

Warp makes terminal titles searchable and editable. Windows Terminal searches the focused pane’s output and supports moving between matches. Apply both patterns to GoHarness’s existing dock. Let users rename and select a terminal by title or project, then search that pane’s buffered output. The Find field should support forward and backward matches and return focus to the same shell on Escape. Make the focused pane visible in a split, and keep shell control keys available. Use Cmd+F on macOS and scope Ctrl+Shift+F to the terminal on Windows and Ubuntu. [Warp vertical tabs](https://docs.warp.dev/terminal/windows/vertical-tabs/#tab-management) · [Windows Terminal search](https://learn.microsoft.com/en-us/windows/terminal/search) · [VS Code terminal keyboard behavior](https://code.visualstudio.com/docs/terminal/advanced#_keyboard-shortcuts-and-the-shell)

## Judge the pass by three completed journeys

Exercise the first-session flow with a fresh profile and the scripted provider. The test should confirm that the app returns to the selected project after setup and that the starter prompt remains editable before sending. Exercise two simultaneous sessions in separate projects, then use the global list to reach the right request and verify that its count changes only after resolution or run termination. Open two real shells in separate folders, rename and switch between them, search for output unique to each pane, and check that Escape returns input to the intended shell. Report native GUI, packaged runtime, and build checks with their actual platform and architecture coverage.

Follow-up research would benefit from observing repeat users and measuring time and mistakes across those same journeys. It can then inform decisions about a unified recent-session catalog, session handoff after an app restart, and confirmation before quitting with live terminals. A separate working-tree review could help users compare what an agent proposed with the current files, including edits made through a shell. Terminal handoff needs a clear promise about which parts of the previous workspace reopen.
