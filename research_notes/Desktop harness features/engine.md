# GoHarness capabilities available to Desktop

## Takeaway

The bundled engine can expose verification evidence, Markdown session export, and project-relative file references without an upstream change. Plan and Build are engine modes selected when a helper starts. The HTTP API can stream Plan's approval request, but the TUI alone implements the automatic handoff to Build.

## Cited findings

- **Version and contract.** The local `v1.1.0` tag resolves to `e53bf475ff135c18323780c7eb5ff7b9ce37166e`. A committed comparison from the tag to local HEAD found no differences under `cmd/harness`, `internal/core`, `internal/localapi`, `internal/runtime`, or `internal/session`. The existing HTTP protocol supports project info, sessions, one active run per server, run events, user input, and cancellation. It accepts a prompt and recovery acknowledgment per run. The chosen model, agent, and project belong to the helper and appear in `GET /v1/info`. [API guide](https://github.com/Sanidhya14321/goh/blob/v1.1.0/docs/USER_GUIDE.md#http-api) · [Helper info](https://github.com/Sanidhya14321/goh/blob/v1.1.0/internal/localapi/server.go#L96-L112) · [Run admission and body](https://github.com/Sanidhya14321/goh/blob/v1.1.0/internal/localapi/server.go#L233-L285)
- **Verification.** Engine `run_finished` includes duration, status, and when provided, outcome and `verification_detail`. Details include change tracking and evidence fields such as source, command, kind, scope, passed, exit code, and revision. `verified`, `unverified`, `no_changes`, and `failed_verification` are distinct engine outcomes. A successful tool result or a successful overall run alone does not establish that edits were tested. Desktop's stream allowlist currently omits the evidence and duration. [Runtime event](https://github.com/Sanidhya14321/goh/blob/v1.1.0/internal/runtime/runtime.go#L1551-L1579) · [Verification semantics](https://github.com/Sanidhya14321/goh/blob/v1.1.0/docs/USER_GUIDE.md#headless-cli) · [Desktop event filter](../../internal/desktop/stream_display.go)
- **Export.** The executable supports `goh sessions export ID --session-dir DESKTOP_SESSION_DIR --format markdown --output ABS_PATH`, with `--include-tools` available separately. It uses an exclusive session lock, emits unredacted content, and publishes to a new destination with a hard-link operation that refuses to overwrite. Filesystems lacking hard-link support can reject the export. [Session commands](https://github.com/Sanidhya14321/goh/blob/v1.1.0/cmd/harness/sessions.go#L46-L70) · [Export invocation](https://github.com/Sanidhya14321/goh/blob/v1.1.0/cmd/harness/sessions.go#L158-L190) · [Atomic export helper](https://github.com/Sanidhya14321/goh/blob/v1.1.0/internal/session/export_file.go#L11-L43) · [Session guide](https://github.com/Sanidhya14321/goh/blob/v1.1.0/docs/USER_GUIDE.md#sessions-and-recovery)
- **File and agent references.** Plain prompt text can contain project-relative `@path` or `@"path with spaces"`. The runtime enforces containment, deny rules, file type, and size, and emits real `files_attached` and `images_attached` events. Text attachment limits are five files, 64 KiB each, and 256 KiB total. Invalid, denied, unsupported, and oversized text references can remain in the prompt as plain text. Agent mentions are resolved separately and reported through `agents_mentioned`. [Reference parser and limits](https://github.com/Sanidhya14321/goh/blob/v1.1.0/internal/runtime/file_mentions.go#L24-L117) · [Attachment and agent events](https://github.com/Sanidhya14321/goh/blob/v1.1.0/internal/runtime/runtime.go#L670-L690)
- **Plan, Build, and profiles.** `goh serve --agent plan|build` applies the engine's modes. Plan prevents editing and shell or external tool execution. `--profile` selects a defined configuration profile. Leaving flags off preserves the existing configuration precedence. The Plan-only `plan_exit` tool asks for permission, then stores a handoff on the runtime instance. TUI reads it and starts Build after completion. The HTTP handler ends after the current run, so this does not switch an HTTP session. `goh agents` provides human-readable columns with project/config discovery. The Desktop-managed provider path currently selects a generated single-model config. - **Projects, worktrees, and change history.** The existing directory picker can open a worktree. The CLI `goh worktree NAME` depends on Git, creates or reuses a sibling checkout on a `goh/NAME` branch, and then launches the interactive terminal UI. The list command returns human-readable Git output. Engine `changes list|diff` reads session file checkpoints and opens the journal with a writer lock. Checkpoints can be best effort and differ from a complete Git diff. [Worktree implementation](https://github.com/Sanidhya14321/goh/blob/v1.1.0/cmd/harness/worktree.go#L15-L69) · [Changes CLI](https://github.com/Sanidhya14321/goh/blob/v1.1.0/cmd/harness/changes.go#L56-L106) · [Checkpoint scope](https://github.com/Sanidhya14321/goh/blob/v1.1.0/docs/USER_GUIDE.md#file-checkpoints)

## Inferences

- Add a compact run result with a clear distinction between verification performed, changes with no proof, failed checks, and no changes. Forward typed, bounded evidence from the host. An omitted outcome should stay unspecified. Use journal records if completed-run evidence needs to persist across reopening.
- Offer Markdown export from the session with a native save dialog. Validate that the requested session belongs to the selected project and use the application's shared session directory and absolute engine path. Leave tool records off by default and explain that exported content can contain private material. Export an idle session and surface a busy error if a concurrent run takes its journal lock.
- Add a project-relative file reference picker that inserts escaped text into the composer. A file becomes attached only after the real engine event confirms it. Keep attachment reads in the engine so its path permissions and size limits stay in effect.
- When implementing mode selection, offer Default, Plan, and Build. Capture the selection when submitting, bind it to the helper, verify the reported agent, and recycle an idle helper when it no longer matches. Preserve writer locks and approval routing across modes. Treat a Plan handoff as an explicit switch with accurate UI wording until the HTTP API publishes handoff state.
- Scope worktree discovery to a read-only feature with a typed listing and an installed Git dependency. Use the existing picker for opening paths. Keep session checkpoints labeled separately from working tree changes and defer mutation until conflicts and journal locks are handled.

## Gaps

- This research used local tag source and did not execute desktop or engine runs. The packaged fixture should test at least no changes, passed/failed checks, fresh session export, and real attachment events.
- Provider-management and custom agent/profile choice need typed discovery across engine-owned and Desktop-generated configurations. The current HTTP helper exposes only its effective configuration summary.
